## 1. Tasks and protocol

- **Datasets: 18 classification tasks.**
  - Images: MNIST and Fashion-MNIST (Keras copies, standard 60000/10000 split).
  - 16 tabular datasets from the Penn Machine Learning Benchmarks (PMLB), with continuous, categorical, binary and mixed
    features and 2–26 classes.
  - *Dev* (used to develop the DFG adaptations): optdigits, magic, kr_vs_kp, satimage, spambase.
  - *Held out* (touched only after the adaptations were frozen): mnist, fashion_mnist, adult, letter, pendigits,
    connect_4, dna, nursery, ring, twonorm, phoneme, waveform_40, mushroom.
- **Learning curves.** A fixed test set: the standard 10000 for the images, a fixed random 25% (at most 10000) for PMLB.
  The training sets are nested prefixes of a seed-specific permutation of the rest, for n = 100, 300, 1000, 3000, 10000,
  30000, 60000 up to the pool size, plus the full pool. Three seeds.
- **The MLP** (`mlp.py`) is a reasonably tuned, standard setup:
  - architecture: 2 hidden layers of 256, ReLU, softmax cross-entropy, Adam, batch 128;
  - inputs: standardized continuous features, one-hot categoricals;
  - steps: min(10000, max(2000, 50 epochs));
  - tuning: learning rate ∈ {1e-3, 3e-4} and the stopping checkpoint chosen on a 10% validation split, then the
    network is retrained on all n points with that choice.
- **Compute rule.** Each DFG fit must use at most the FLOPs of one MLP training run at that n, 6P·128·S
  (`harness.mlp_flops`). The MLP's model selection costs 3 runs.
- **References** (not part of the comparison, for calibration): multinomial logistic regression on the MLP's encoding
  (`linear`, the "kernel background" alone), and sklearn's histogram gradient boosting with default settings (`hgb`), a
  strong tabular learner.

## 2. Three adaptations of DFG

DFG as written assumes ±1 inputs, the uniform distribution and binary labels. Three independent builders each wrote one
adaptation that keeps its core:
- greedy rounds of exhaustive candidate tests against the least-squares residual, with union-bound thresholds;
- composition classes;
- block moves;
- a least-squares readout;
- a FLOP budget.

Each builder developed only on the dev datasets and then froze its design. The design with the best dev score
(mean log2 error ratio against the MLP) was designated the primary proposal *before* any held-out run.

| design | discrete features (the dictionary) | test constant c | readout | dev score: mean log2(err / MLP err) |
|---|---|---|---|---|
| `dfg_bits` (most faithful) | each input → ±1 bits (one-hot categories; 6–12 thermometer bits at training quantiles per continuous input); *characters* (products of bits from different inputs), degrees 1–2 every round, 3–4 when the budget allows; extensions S∪{j}, S∪{j,l}; local Walsh transform; linear and spectral (u·x)² blocks | 1 (DFG's) | ridge LS (leave-one-out ridge) → softmax refinement | +0.15 |
| `dfg_gates` | *literals* [x_j > t] at 16 quantiles, [x_j = v], and negations; *gates* = ANDs of up to 3 literals; pairs exhaustively on a budgeted subsample, extensions g∧l of current gates; linear block | 0.5 | LS or softmax, chosen on a 10% split, refit on all n | +0.07 |
| `dfg_dirs` (primary) | gates [u·z > t], hinges and squares (u·z)² on a finite set of *axes*: the coordinates, plus directions derived each round (per-class linear discriminants, spectral eigen-directions of the residual, the residual's class-mean difference inside an accepted gate's region, prototype points); products of accepted features with gates (composition); linear block | 0.8 | softmax, λ by cross-validation | +0.06 |

All three:
- run DFG's multi-class test: a χ² statistic of the whitened residual summed over classes, with a union bound over each
  candidate class;
- accept candidates in rounds;
- keep a linear block;
- count every FLOP against the one-MLP-run budget.

Two of them loosened DFG's constant c on dev data, because with c = 1 growth stopped after a few rounds on dense
real-world signal. dfg_bits kept c = 1.

Each folder has a `DESIGN.md` with the details and the dev history.

## 4. What this says

**Where DFG holds up** (Numerical): low-dimensional tabular problems whose signal is a handful of thresholds,
categories or short interactions. On those, a discrete dictionary plus explicit tests is as good as an MLP, and often
better at small n. Its explicit, union-bound-gated growth then works as built-in regularization.
- *ring:* two Gaussians that differ in variance, which needs |x|-type features. Thermometer bits express those
  directly, and dfg_bits gets 0.13 error at n = 100 against the MLP's 0.29.
- *dna:* sparse categorical motifs.
- *waveform:* nearly linear. Here the regularized linear readout is the whole story, and plain logistic regression
  does as well.

**Where it falls behind.**
- *Tabular data needing many interacting features at large n:* letter (26 classes), pendigits, connect_4 (game
  positions) and phoneme.
- *Images:* everywhere above n ≈ 300.
  - At large n the MLP reaches about half of DFG's error, and the gap grows with n. dfg_bits and dfg_gates end up close
    to plain logistic regression.
  - dfg_dirs, whose dictionary is thresholded linear directions (the same kind of unit as an MLP's), is the best of the
    three on images. It is still 1.5× the MLP's error on MNIST at n = 30000.

**Why** (Heuristic). In Part 6, DFG beat gradient descent on sparse Boolean targets. Exhaustive search over a
dictionary that contains the target's features pays only about ln N in samples, and the dictionary fit within the
networks' FLOP budget. On standard tasks the premise fails in two ways:
- *The features that matter are not in any small enumerable dictionary.* On images, the useful hidden units are
  directions spread over hundreds of correlated pixels, each with a small weight. That is a continuous family:
  - A product of a few bits or a short AND of thresholds is a poor approximation of one such unit.
  - DFG's directional moves (spectral eigen-directions, class discriminants, local mean differences) generate only a
    few candidate directions per round, from statistics of the current residual.

  An MLP's gradient step instead updates hundreds of directions at once, each pulled toward the residual. In effect it
  is a continuous, parallel version of DFG's spectral move, iterated thousands of times. In the continuous family,
  local search is the efficient search, and enumeration is not.
- *The tests become the bottleneck.* Union-bound tests are built to stop false features on sparse targets. On dense
  real-world signal — many weak, correlated effects — they stop growth after a few rounds, and two of the builders had
  to weaken the test constant c to get growth at all. The MLP has no such gate. It fits everything and relies on early
  stopping, which is the better trade when the signal is dense.

**What the experiment does not show.**
- It does not show that no discrete learner can match MLPs on images.
- It does not show that DFG's tabular wins are robust to a stronger MLP. The `mlp_best` row bounds this from the MLP's
  side: some DFG wins shrink against it, and dna, ring and waveform remain.
- It does not show the comparison with gradient-boosted trees. `hgb`, also a discrete feature-growing learner, is the
  strongest tabular reference here, and it is better than both the MLP and DFG on adult, phoneme and at large n.

## Reproduce

```
cd study/standard_tasks
python data.py                              # downloads and caches the datasets
python mlp.py <dataset> ...                 # MLP baseline -> results/mlp__<dataset>.json
python baselines.py linear|hgb <dataset> ...
python -c "import harness, importlib; harness.evaluate(importlib.import_module('dfg_bits.learner').Learner(), ['mnist'])"
python compare.py dfg_bits dfg_gates dfg_dirs     # RESULTS.md
```
