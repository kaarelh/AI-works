**Points to check before sending:**

- **Opted-out people are still in the output, marked `opted_out: "Y"`.** The rules ask for this, but your send list must filter on it, for example `[p for p in result if p["opted_out"] == "N" and p["email"]]`. Because opt-outs are merged across all of a person's rows, a single opted-out duplicate suppresses the whole person. That's the safe behavior.
- **People with only a phone number** have `email: ""` and need to be excluded from the email send (the filter above does this).
- **Bad `updated` values raise a `ValueError`** instead of being skipped silently. The rules say this field is always present, so a parse failure means bad data you'd want to know about. Leading and trailing whitespace is tolerated.
- **Interpretation choices** where the rules were ambiguous:
  - Gmail normalization is only applied when the address has exactly one `@`.
  - "Digits" means ASCII 0–9 only.
  - The ZIP+4 check also accepts a 4-digit prefix (e.g. `2139-4307` becomes `02139`), since Excel can drop the leading zero there too.
  - Last names are compared with `casefold()`.
  - A gmail address like `+foo@gmail.com` normalizes to an empty local part and is treated as invalid.
- **Matching on phone requires both rows to have a non-empty last name.** Two rows with the same phone and blank last names are not merged unless something else links them, such as a shared email.
