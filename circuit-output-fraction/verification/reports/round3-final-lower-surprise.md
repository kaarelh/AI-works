# Final referee report: lower-surprise

**Verdict.** needs major fixes. There is one major issue: thm:surprise(b) is stated in a pure black-box model. There thm:blackbox already gives a stronger bound whenever D(E) < 1/3, so (b) does not support the reading 'once an envelope is certified, the 2^{sigma_u} term cannot be avoided' that the paper, intro, discussion and README rest on it. LENS A (re-derivations):
(1) prop:proposal(a). psi is a bijection from R*={r: phi(psi(r))=r} onto X*={x: psi(phi(x))=x}, with inverse phi. Seeds with P_R(r)=0 contribute 0 on both sides. Each term is at most D(x). So E W <= p for every C, psi, phi, tau and every self-certifying law.
(2) prop:proposal(b). On the covered set, min(...) = D(x), so E W >= (1-eps/2)p. phi is injective on X*, so the covered mass is at most tau, hence tau >= (1-eps/2)p and mu >= (1-eps/2)/K >= 1/(2K) for eps <= 1. The KL lower end satisfies ell >= mu_hat - sqrt(2 mu_hat ln(2/delta)/N). With the multiplicative Chernoff bound at gamma = eps/8, N = cK eps^-2 log(1/delta) gives ell >= (1-eps/2)mu, and (1-eps/2)^2 >= 1-eps. Correct.
(3) The special cases are valid: the envelope law gives W/tau = C min(1/phi, 1) with tau = Z, which is thm:envelope(iii). Witness lists are exact.
(4) thm:surprise(a). The coupling with the zero function is right. Soundness gives Pr[L>0] <= delta. The S_b partition the cube, so sum_b Pr_pi[hit S_b] <= T. Summing over b and over the 2^ell arguments gives T 2^ell >= (1-2delta)2^k. Tightness holds: a proposal uniform with j bits fixed has tau = 2^-j, K = 2^{k-j}, and prop:proposal(b) gives O(2^{k-j} eps^-2 log(1/delta)).
(5) thm:surprise(b). The family and the coupling direction are right. With pi_0 on both circuits, U <= (1+eps)p_0 < 1.5p_0 = p_1 on C_0, and U >= p_1 on C_1. The C_0 run does not depend on S', and averaging over S' gives T 2^-k >= 1-2delta. The constant 1-2delta is right because the hypothesis includes containment.
(6) Cost formula. Z is now defined per estimator. The per-leaf ratio 1+eps/(2t) and confidence delta/t give O(t^2 eps^-2 log(t/delta)) sum_lambda 2^{sigma_u(lambda)}, and an even spread gives t^3 2^{sigma_u/t}.
(7) Citation. hilton2024surprise (Hilton, ARC blog, 25 June 2024, confirmed by web search; the page itself could not be fetched) defines surprise accounting as additive in bits, which matches the paper's parenthetical.

## New findings

### 1. [major] p2-lower.tex thm:surprise(b) (ll.90-97) and its gloss at ll.128-131; also sec-intro.tex ll.41-43 and ll.143-145, sec-discussion.tex ll.20-22 and ll.33-37, README.md l.22

**Problem.** (b) is stated in the pure black-box model. The verifier accesses C only through evaluations and must be 'delta-sound for upper bounds on all circuits'. Those hypotheses are exactly those of thm:blackbox. On C_0 the verifier outputs U <= (1+eps)p_0 < 1.5p_0 with probability >= 1-delta. Taking 2^{-k'} in [1.5p_0, 3p_0), thm:blackbox gives T > (1-2delta)/(3p_0) = (1-2delta)2^k/(3D(E)). That exceeds (b)'s (1-2delta)2^k whenever D(E) < 1/3; for example, at k = 10 and D(E) = 2^-20, thm:blackbox gives 4.8e8 against 921.6 (fam_b.py). So (b) adds nothing in the regime where the envelope explains any bits. In this model the envelope E cannot be certified and is of no use to the verifier. The theorem is true, but it does not support the reading used throughout: 'once an envelope is certified, the 2^{sigma_u} sampling term cannot be avoided ... by any method that treats the rest of C as a black box'.

**Proposed fix.** Change the hypothesis of (b) to the hybrid model that the gloss describes. The verifier knows E (as after a certified domination proof) and need only be delta-sound for upper bounds on circuits C with C => E, equivalently C = E AND G with oracle access to G for arbitrary G. The proof is unchanged: C_0 and C_1 satisfy the promise, and the runs differ only on a query in E AND S', which is contained in S'. The planted circuits f OR 1_{H_t} in the proof of thm:blackbox violate the promise, so thm:blackbox no longer applies. Add the matching upper bound: sampling (y,x) ~ D|E and evaluating G is sound on all such C and uses O(2^{sigma_u} eps^-2 log(1/delta)) evaluations. Then (b) is a two-sided characterisation, and the sentences in p2-lower, the intro, the discussion and the README become accurate.

### 2. [minor] p2-lower.tex cost formula (ll.64-68) and closing paragraph (l.124 '|pi|+2^{sigma_u(pi)}'); abstract and README 'poly(|pi|)+2^{sigma_u}'

**Problem.** def:pcis writes each statistical node's sample cap in unary. A complete argument therefore has |pi| >= cap >= about 2^{sigma_u} eps^-2 log(1/delta), so the poly(|pi|,|C|) term already subsumes the 2^{sigma_u} term, and the two-part MDL-style cost |pi| + 2^{sigma_u(pi)} collapses as written. thm:certenv avoids this by charging poly(m), where m excludes the caps. Also, c_s is given only for deterministic envelopes and thm:sis. It is missing for a non-deterministic Phi through thm:envelope, where it is O(|C|+|Phi|), and for unions through thm:certenv, where it is |C| + m + n^2 + nT.

**Proposed fix.** Define |pi| in the formula as the size of the argument's deductive content (envelope or pieces, proofs, circuits), excluding the unary caps and budgets. Alternatively, say that the caps add O(2^{sigma_u} eps^-2 log(1/delta)) to |pi| linearly. Add the two missing c_s cases.

### 3. [minor] p2-lower.tex prop:proposal ll.4-9 ('rational circuits q_i(r_<i) in [0,1] ... need no check')

**Problem.** 'q_i in [0,1]' is a promise about all prefixes that the verifier cannot check globally. A prover's circuit may output 1.5 or -0.2 on some prefix, and the text does not say what the verifier then does. Likewise, PC weights must be nonnegative and are normalised by the verifier, and the envelope law needs Z > 0. 'Rational circuits' with arithmetic gates can also produce exponentially long numbers. That leaves soundness intact but breaks the polynomial running time of computing P_R(R).

**Proposed fix.** State the convention. The verifier clamps each q_i to [0,1] and uses the clamped value for both sampling and the pmf, so every circuit defines a valid law. Alternatively, on any out-of-range value it gives the node [0,1]; this is also sound, because on the no-abort event the samples coincide with samples from the clamped law. Require nonnegative PC weights (checked locally) and Z > 0. Take q_i as Boolean circuits that output numerator and denominator in binary, so bit lengths stay polynomial.

### 4. [minor] sec-intro.tex l.30 ('Clipped importance weights make this sound for any proposal (prop:proposal)')

**Problem.** 'For any proposal' contradicts prop:proposal and its closing warning (p2-lower ll.51-54). A proposal whose pmf and sampler are supplied separately is exactly the unsound case: E W can be inflated arbitrarily.

**Proposed fix.** Say 'sound for any proposal whose sampler and likelihood the verifier derives from one object (self-certifying form, prop:proposal)'.

### 5. [minor] code/rareprob/tilting.py proposal_lower_bound (ll.134-148)

**Problem.** This is the only code for prop:proposal, and nothing calls or tests it. Its docstring claims a 'sound lower bound on p from ANY product proposal Q (lower-bound arguments)', yet it reads Q.sample and Q.logpmf directly from an untrusted object. A Product subclass whose sampler always returns 111 while its logpmf claims 1e-3 yields lo = 0.996 for p = 1/8 (scratchpad/lower/code_evil.py). That is the attack prop:proposal warns about. argument.py sanitises prover objects for this reason, but this function does not. M <= 0, NaN or inf give lo = -0.96 or NaN. hi = +inf lies outside [0,1], contrary to def:sound. For genuine Product inputs it is sound: 0 violations in 1500 brute-force instances (code_prop.py).

**Proposed fix.** Copy Q.q into a fresh float array, check that it is finite and in [0,1], and build a new Product from it. Require a finite M > 0, otherwise return [0,1]. Return hi = 1.0. Add a brute-force test like code_prop.py. Alternatively, delete the function and drop the README mention of 'proposal-based lower bounds'.

### 6. [minor] sec-experiments.tex ll.170-179 (fig:surprise caption and paragraph) and experiments/exp_arguments.py l.152 (depends on this topic; numbers not judged)

**Problem.** The paragraph says the sample count grows as 2^{sigma_u} 'as thm:surprise says it must'. thm:surprise(b) is a worst-case lower bound over a planted family for black-box residuals; it says nothing about this particular trigger instance or about a verifier that reads C to check a DRUP proof. Also, the x-axis 'unexplained_bits = k - j' omits log2(1/Pr[R]) for the body R, so it is not sigma_u = log2(Z/p) as p2-lower.tex l.60 defines it. trigger_circuit only guarantees Pr[R] >= 0.05, so the offset can be up to about 4.3 bits.

**Proposed fix.** Write 'consistent with the lower bound of thm:surprise(b) (after the hybrid-model fix)' instead of 'says it must'. Either label the axis as unrevealed trigger bits k - j, or plot sigma_u = (k - j) + log2(1/Pr[R]) using the exact p the script already computes.
