# Fixes after the final round

## code-semantics

Threshold gates now have exact semantics everywhere. Circuit.add canonicalises (w, t) into an equivalent integer form with circuit.thr_canonical. Floats are read at their exact binary value, ints and Fractions as given. The weights are scaled by their lcm denominator and divided by their gcd. The threshold is scaled the same way, rounded up with an exact ceil, and clipped to [sum of negative weights, sum of positive weights + 1]. t = +inf / -inf maps to constant 0 / 1. NaN and non-finite weights are rejected.

The evaluator (thr_eval) sums exactly:
- int16, int32 or int64 accumulators when the total size of the weights and t allows it (now about 2x faster than the old float path);
- table lookup for fan-in up to 16 with huge weights;
- Python integers otherwise.

CONST parameters must be 0 or 1. True, 1.0, np.int64(1) and the like are accepted; 2, 0.5, -1, None and NaN raise ValueError. This holds in add(), const() and the raw constructor, and every module reads CONST through circuit.const_value.

Every module now reads this integer form with no tolerance:
- nnf.py: counter expansion on the scaled weights, need = T + shift.
- ve.py: exact tables.
- affine.py: exact propagator; the weights of a repeated child are added up.
- localthr.py: threshold read from the canonical form.
- meta.as_block_threshold and tilting.py: integer t; [S >= t] in int64 in both W and phi, so phi dominates C exactly.
- exact.py: adds an independent Python-integer reference evaluator.
- cnf.py: CONST through const_value; THR stays a sound relaxation.

All 1e-12 tolerances tied to the old semantics are gone. Other findings in my files that are fixed:
